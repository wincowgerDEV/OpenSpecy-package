build_lib(): source data to release and assessments

This canonical visual companion follows the staged library-only overhaul, restart-safe per-dataset checkpoints, the bounded final join, and deferred downstream artifacts. Hover a box for details; pan and zoom to follow the flow.

Current production contract: the ignored rawrefdata/updatedv1/datasets.csv manifest admits only reviewed <dataset>/Processed/CleanedOS_raw.rds files. The tracked slug-keyed metadata dictionary supplies one unique descriptive library_name and derives spectrum_origin as Observed or Computed for every admitted dataset. The driver calls build_lib(..., artifact_scope = "libraries", reuse = TRUE, dedupe_correlation_threshold = 0.99) separately for every admitted dataset, applies those canonical fields before writing immutable raw/derivative/no-baseline recipe/type artifacts and a hash/count manifest under that dataset's Processed/ folder, and releases resident matrices before continuing. Exact hashes and strict same-dataset/type/identity correlation > 0.99 repair only internal dataset redundancy. Derivative and no-baseline artifacts run dataset-local generic reassignment and ordinary bounded pruning with cross-class closure disabled; min_n preserves reviewed small classes. Only completed manifested artifacts enter the final 5,000-column file-backed join. That join validates rather than repairs canonical metadata, preserves every survivor, qualifies only colliding cross-dataset sample_name values with the dataset slug while retaining source IDs/provenance, performs no cross-dataset deduplication, reassignment, pruning, medoid selection, model fitting, or legacy comparison, and serializes one recipe/type before creating the conventional unified raw.rds, derivative.rds, and nobaseline.rds files. Metadata-only corrections to a completed release use a signed immutable child-release patch with exact target-only equality proofs; every such rule must be integrated at this dataset boundary before the next full rebuild. Source hashing remains capped at 20,000 columns, correlation blocks at 256 by 5,000, metadata updates at 100,000 rows, diagnostics at 1,000 representative values, and merge/recipe blocks at 5,000. Every dataset-local removal remains in a hashed v3 OpenSpecy quarantine shard. Medoids and models are explicitly deferred to a later rebuild_lib_artifacts() request.

Call build_lib(one_dataset, artifact_scope = "libraries")
one admitted source · one Processed output
The workflow iterates the exact admitted manifest in source order. Each call owns only one CleanedOS source and its dataset-local output directory.
Official checkpointed mode?
output_dir + artifact_scope supplied
An explicit output directory selects the checkpointed workflow. artifact_scope chooses complete or library-only artifacts; supplying x with no output directory preserves the composable return.
Composable custom build
named recipe OpenSpecy objects
The compatibility path applies requested normalization, lookups, filters, deduplication, processing, and pruning without official release side effects.
Validate intake manifest, paths, and helper data
reviewed CleanedOS list · explicit output · adjacent data/
The ignored manifest selects exact one-folder/one-cleaner outputs only after source license/use basis, FTIR/Raman type, intensity/transmission semantics, approved diagnostic plot, warning-free check_OpenSpecy(), serialization recheck, and hashes pass. Intake failures are written separately. Curated helper tables remain version controlled under workflows/data/.
Fingerprint build contract
SHA-256 files + args + package + code + runtime
A deterministic signature covers inputs relevant to safe restart. Any changed source, lookup, argument, package contract, builder code, Git state, or model runtime invalidates downstream reuse.
reuse = TRUE and dataset signature matches?
dataset-local stage decision
Only completed artifacts with compatible source, lookup, argument, and code signatures are reused. A changed dataset invalidates only its own work.
Load completed dataset checkpoint
status = reused
Raw, derivative, no-baseline, assessments, and quarantine have restart points. This scope never creates medoid/model checkpoints.
Prefilter and stage one frozen dataset
quarantine first · retained rows only · bounded blocks
The driver never discovers arbitrary cleaners. It reads one exact admitted CleanedOS output, verifies its fingerprint, captures exact and strict identity-local correlation removals in quarantine, and stages only retained metadata and spectra. The matrix is released before the next dataset starts.
Standardize identities and metadata
canonical internal and app-facing values first
Stable identities are cleaned and populated canonical values win; reviewed aliases such as user_name fill only blanks before external joins. The tracked dataset dictionary supplies a nonblank descriptive library_name, and admitted origin supplies exactly Observed or Computed in spectrum_origin. Fills and conflicts are reported.
Complete dataset-local joins and filters
100k-row joins · 1k diagnostic values · no full copy
Exact class and canonical source lookups run before reviewed regex fills and hierarchy updates. Diagnostics preserve exact totals with bounded representative values. Exact hashes and strict >0.99 identity-cohort correlation removals are confined to this dataset and captured in its quarantine; no different datasets coexist here.
Build three recipes
raw · derivative · nobaseline · HDF5 blocks
Recipe staging reads each 5,000-column block from the temporary merged core, materializes an ordinary aligned OpenSpecy block, and writes raw, derivative, and no-baseline HDF5 artifacts with preserved metadata/attributes. The merged core is deleted only after all recipe artifacts close successfully (and is also cleaned after errors). Above the frozen 250,000-spectrum trigger, recipe values remain file-backed and later quality and partition work stays blockwise. Recipe serialization swaps only the S/N metadata column and restores it after saving instead of cloning the complete table for every recipe.
Class and polymer-group hierarchy
exact + regex leaves · complete type/group crosswalk
Exact mappings win; regex fills blanks and clashes remain fatal. Repository class tables are read as UTF-8, and stereochemical SMILES backslashes remain identity data rather than path separators. Named monomers and small organic molecules map directly to organic matter/not plastic. Every final material class must have exactly one material_type and material_group route; the narrow vinyl alcohol/acetate/acetal group does not collapse its leaves. Reviewed non-generic classes remain authoritative at every support count: min_n may bound ordinary correlation removals but cannot rename or delete a class merely because it is small.
Retain and route generic materials
generic labels retained · unidentified rows reviewed
Non-generic rows without a stable identity follow remove_other. Paint, varnish, rubber, latex, resin, unresolved composite, other plastic, and other material spectra with a generic review label remain for constrained nearest-class correlation reassignment. A row with no finite eligible candidate remains generic and audited.
Quality gates and bounded correlation views
stream recipe/query blocks · no production square cache
The maintained large build performs quality work one file-backed block at a time, then restores derivative/no-baseline generic reassignment and ordinary active-set pruning with bounded normalized-spectrum and correlation blocks. When every active candidate already has the target class, ordinary pruning cannot remove any row, so an exact output-identical short-circuit records the avoided square allocation and skips that scan. Sparse opposing-class pools first find exact different-class leaders, then discharge queries as soon as a same/unknown-class witness wins beyond deterministic tie tolerance; only true winning conflicts are rescored in their original bounded tile, with no full fallback rescan. Otherwise the same exclusion range, deterministic ID ties, and min_n floor apply as in-memory prune_lib(); cross-class closure remains disabled. Exact hashes and strict source/type/identity correlation deduplication remain a distinct earlier policy.
Dataset recipe/type manifest and quarantine
immutable RDS · SHA-256 counts · complete ledger
The dataset is durable only after all three recipes, every present spectrum type, canonical library_name and spectrum_origin values, assessments, and quarantine validate and their paths/counts/hashes are recorded. The process then releases its matrices and advances.
Raw libraries by type
Raman 200–4000 · FTIR 400–4000 · NIR 4000–12000
libraries$raw is keyed by spectrum type. Each aligned OpenSpecy object drops all-NA metadata columns, then stably orders the remainder from least to most missing. Raw spectra remain available for reference matching or explicitly requested random-forest training.
Derivative libraries by type
CO2 → tails → SNR ≥ 2 → generic reassignment → bounded prune
FTIR CO2 is flattened only above a ratio of 2. Finite-support high tails are trimmed and reassessed; failed corrections and SNR below 2 are dropped. Generic rows are then reassigned to their nearest eligible established class before ordinary active-set pruning; type/range flat checks follow.
No-baseline libraries by type
CO2 → tails → SNR ≥ 2 → type/range flat gate
The same checkpointed blockwise quality and type/range gates run on baseline-removed spectra before the immutable dataset manifest is closed.
Final typed join
one recipe/type · no filters · 5,000-column HDF5 blocks
Only manifested survivors are read. Source hashes are checked before and after consumption. Canonical library_name and spectrum_origin values must already match the dataset manifest; the join does not synthesize them. Cross-dataset content-ID collisions are retained and made globally unique by qualifying only the colliding sample_name with its dataset slug; source_dataset and source_sample_name preserve provenance. Aligned IDs, axes, values, NA envelopes, metadata, and attributes are validated before each typed artifact is made durable.
Unified recipe files
raw.rds · derivative.rds · nobaseline.rds
Type shards are combined only at the last serialization boundary. A signed index records every dataset artifact and final payload.
Medoids deferred
no PAM or model-range closure in this tranche
A later explicit rebuild_lib_artifacts() request may consume the completed unified libraries.
Models deferred
no training or model comparison in this tranche
No medoid or model payload/checkpoint is allowed in the staged overhaul release.
Deferred comparator load
not executed by the library-only driver
Postbuild compatibility may later load legacy artifacts, but it cannot trigger medoid or model creation in this tranche.
Compatibility inventory
IDs · axes · metadata · counts · shape
Candidate and legacy artifacts are compared for identifiers, axes, metadata, classes, techniques, warnings, and object validity.
Deferred grouped splits
future physical ID + exact content groups
No holdout split is created during the library-only overhaul. A later frozen assessment may group physical replicates and transformed duplicates without leakage.
Deferred holdout identification
not executed in this tranche
Reference holdout scoring is reserved for a later explicitly frozen assessment.
Deferred model identification
no model fit or score
The library-only release does not build, load for scoring, or compare candidate models.
assess_spec(report = "all")
one full in-memory call per artifact
Vectorized indexed report expansion summarizes per-check/status counts, findings, rates, examples, and unavailable checks across each complete old/new artifact without wrapper-level chunks.
Old → new summaries
wide adjacent metrics · largest findings first
Old/new values occupy adjacent columns. Macro accuracy, misidentification counts, absolute model correlations, and merged warning/error rate shifts sort descending; assess_spec passes are omitted.
Assessment checkpoints
split · reference · model · assess_spec
Long comparison components are saved independently and reused only under a compatible candidate/legacy signature.
Deferred comparison review
candidate versus frozen comparator
The current release retains dataset-local cleanup and quarantine evidence. Full reference, medoid, model, and functionality comparisons remain a separate later tranche.
Immutable versioned release
SHA-256 payloads + aliases + aggregate + manifest
Every validated standalone and aggregate artifact is promoted to a signature-named release. An existing path must have the same SHA-256 payload or promotion fails. A post-join metadata correction creates a signed child release, never mutates this parent, and proves spectra, axes, IDs, attributes, row order, and all untargeted metadata are identical.
Return library-only index
three unified recipes + typed shards + dataset manifests
The release contains completed libraries and audit evidence only; medoid/model work remains absent and independently composable.
