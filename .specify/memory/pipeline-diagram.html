App Data Analysis Pipeline

How a spectrum or hyperspectral map moves through the bundled Shiny app (inst/shiny/), from local direct-file selection or hosted browser-file mounting to every rendered plot, table, and download. Boxes are colored by role — input, function, decision, user-triggered recompute, output — diamonds mark every point where data shape or a user setting sends processing down a materially different function path, dotted rose lines tap each output back to every upstream point that actually decides whether it exists or what shape it takes, and dashed teal lines show click-driven interaction between outputs (e.g. the Heatmap driving the Spectrum Plot). Hover or focus any box for the exact reactive/function name, source location, and any nuance the short label can't carry.

Constitution Principle X (Data Analysis Pipeline Fidelity): this diagram is the canonical map of the app's analysis pipeline. Deviations from it (new stages, changed branch conditions, new/removed function calls, or a changed output dependency) must not happen incidentally — they must be an explicit part of a plan, and that plan must name the diagram box(es)/decision(s) it changes and update this file. See .specify/memory/constitution.md.
Plan 018 target (not yet implemented): a local direct path or hosted WORKERFS mount stages and validates an H5/ENVI source. Click Run materializes the complete base Specs with lossless compact coordinates/metadata and, only when selected, halo-aware smoothing, S/N classification, and background-to-zero suppression. PCA, K-means, and Hilbert are later full-object as_Specs() transforms over foreground values and source multiplicities; they never expand pixels and preserve background mapping 0. Indexed inspection returns one labeled OpenSpecy without expanding the map.

Hosted Browser File(s)
session-scoped WORKERFS mount
This is the only hosted upload control. The inner-frame picker sends browser File objects, not their bytes, through a capability handshake to the pinned Shinylive shell. The owned outer adapter exposes one composite Blob plus member offsets to webR.FS.mount("WORKERFS", {packages}, sessionMount) and returns only validated mounted paths to Shiny. Mount and read stages report through the central progress popup; replacement or page exit unmounts the prior session path. parent-frame.js · tools/wasm/shinylive-workerfs-bridge.js · patch-shinylive-workerfs.R
Local Filesystem Path(s)
local-only direct picker · no upload copy
The bundled/local app uses one secured shinyFiles picker to resolve normalized, read-only real paths, including multiple files and ENVI companions. It replaces fileInput(), so Shiny does not first copy the source into session temp storage. Shinylive renders only its WORKERFS picker. Both entry paths converge at the same readers and scientific pipeline. Plan 018 · ui.R/server.R: local source picker · parent-frame.js: bindWorkerfsUpload()
Stage Source & Header
validate path, members, header, dimensions · no full map
Plan 018 target: mounted and native paths converge into a session-owned source descriptor. H5/ENVI/ZIP input validates readable members, header, dimensions, axis, and expected bytes but defers spectral materialization until Click Run commits scientific settings. Ordinary small formats retain their compatible dense OpenSpecy read. The original source stays untouched and available for reruns. Plan 018 · server.R: staged_source() · global.R: app_read_uploaded_members() · R/{read_multi,read_envi,read_ext}.R
Passes validity check?
source descriptor or OpenSpecy valid?
Before Run, compact candidates validate source readability, members, axis, dimensions, and size arithmetic without allocating spectra. Already-materialized ordinary input uses check_OpenSpecy(). The completed Run later validates its compact object with check_Specs() before publishing canonical state. Plan 018 · server.R: staged source validation · R/{read_envi,read_ext,Specs}.R
Upload Error (abort)
show_alert() plus the mode-appropriate persistent status fires. Neither a source descriptor nor canonical object is published, so Run and later stages cannot consume a partial source. Plan 018 · server.R: source staging
▶ Click Run
Snapshots every scientific setting and owns canonical analysis publication. A staged source is materialized here unless Recalculate Preview has already materialized it for S/N inspection. Threshold S/N alone enables the background-filter policy, while Spatial Smooth independently decides whether classification receives halo-smoothed or unsmoothed spectra. Readers compact coordinates and metadata losslessly but do not hash spectra or accept PCA, K-means, or Hilbert arguments. Other settings remain passive until the next Run. Every later output derives from this snapshot. Plan 018 · server.R: run gate priorities and canonical_state_gate()
↻ Recalculate Preview
Works before the first Run: if only file paths are staged, it materializes and validates them, then scans the selected S/N basis and retains only histogram values/summary. It never publishes canonical analysis. Central progress makes the potentially long scan explicit; any changed metric, bounds, basis, or sigma keeps canonical results stale until Click Run. Plan 022 · server.R: read_uploaded_files() + recalculate_snr_preview()
Base Specs Materialization
optional smooth/S/N/background + compact descriptors · Run or Preview materialization
Reads full-band spatial tiles/regions, adding Gaussian halos only when smoothing is selected. Threshold S/N enables the optional background filter: it classifies the chosen smoothed or unsmoothed basis and points rejected sources to protected mapping 0. With thresholding off, no background is removed. The reader retains every foreground spectrum exactly once and losslessly compacts grid/metadata descriptors; the genuine profile found no exact spectral duplicates, so it performs no spectral hashing. Readers accept no PCA, K-means, or Hilbert arguments; those operate afterward on the full compact object. Plan 018 · R/{read_envi,read_ext,read_multi,Specs,sig_noise}.R · server.R: canonical_state_gate()
Map data?
source count > 1 (dense or compact)
Uses dense spectrum columns or the compact source count, never the number of unique stored values. A map whose pixels all share one exact spectrum is still a map. A genuine single spectrum takes the "no" path, making Spatial Smooth and Collapse no-ops. Plan 018 · server.R: map guards · R/Specs.R: indexed accessors
Spatial Smooth
dense here · filtered Specs already smoothed once
Dense/ordinary maps retain the existing optional spatial_smooth(). A filtered compact map arrives with the same committed Gaussian transformation recorded, so this stage recognizes provenance and does not smooth twice. A compact map without early suppression uses a bounded Specs smoothing method when requested. Plan 018 · server.R: spatial_data() · R/spatial_smooth.R · Specs transformation provenance
Measured Runtime Failure
depends on: an actual read/allocation/analysis error
Only a caught failure that actually occurs on the mounted/native read or committed analysis path reaches this output, with the failing phase, elapsed time, and recovery guidance. It never rejects a job from a platform-memory estimate. server.R: read_uploaded_files() and canonical_state_gate · global.R: app_upload_failure_guidance()
Signal/Noise Compute
reuse committed source S/N or compute foreground values
Filtered compact maps reuse their per-source S/N and eligibility produced by the batch reader, guaranteeing that particle edges and zero mapping use the same metric. Exact compact maps compute once per unique value and project through the source index; dense/Fully Processed paths retain ordinary computation. Selected-spectrum Quality Findings remain bound to Active Spectrum Inspection, with suppressed pixels handled by provenance. Plan 018 · server.R: signal_to_noise_basis()/signal_eligible() · R/{sig_noise,Specs_methods}.R
Collapse particles?
input$collapse_decision
particle_pipeline_enabled(): true only if the switch is on AND the upload has >1 pixel. Dataset Signal/Noise thresholding applies on both branches and can exclude a pixel from canonical units. Plan 017 keeps that rejection in maps/exports but lets a click inspect the genuinely processed source pixel instead of drawing a synthetic flat line. server.R:1109-1115
Ordinary Process
process_spec() + corrections · foreground values once
The !collapse branch applies the existing correction and processing sequence. For Plan 018 compact maps, deterministic columnwise operations run once per stored foreground value while source mappings and compact metadata remain aligned; range changes update variables. Coordinate-dependent exceptions use their named compact method and update descriptors. This remains the only stage that changes spectral values. Plan 018 · server.R: ordinary processing · R/process_spec.R · R/Specs_methods.R
Identity Pixel Mapping
identity_pixel_mapping()
With Collapse off, an ineligible pixel remains excluded from canonical units. Exact-mode rejection retains Plan 017's source-pixel inspection fallback. When Plan 018's committed background step ran, the source instead points deliberately to the protected zero sentinel and carries suppression reason/provenance; it is never presented as an unchanged measurement. Plan 018 · server.R: identity_pixel_mapping() · Specs source mapping
Particle ID Strategy?
input$particle_id_strategy
All three strategies are backed by OpenSpecy:::.partition_particle_map(), just with different strategy= arguments and pre/post steps — see each box below. server.R:1328-1329, 1495 onward · R/automate_particle_analysis.R:608
Connected Threshold Regions
strategy = "collapse"
Without Correlation Threshold: .partition_particle_map(eligible=signal_keep, strategy="collapse") flood-fills spatially-connected same-eligibility pixels into particles, then Ordinary Process + (if identification is on) Library Identification run once on the collapsed units. WITH Correlation Threshold on: identification runs FIRST per-pixel, then partitioning re-runs with eligible = signal_keep & correlation_keep and material = the per-pixel match, so a region must also share a passing, matching material; a final Ordinary Process + app_aggregate_unit_matches() re-aggregates identification onto the final particles. Needs a real (non-model) library only when Correlation Threshold is on, else blocked with an "unavailable()" diagnostic. server.R:1495-1563, 1349-1354
Spatial Clusters
strategy = "partial_collapse"
Shares Non-spatial Clusters' first pass (PCA + k-means, dotted rose line), then spatially merges same-material connected pixels and re-aggregates matches. Plan 018 keeps the upstream background zero sentinel outside PCA fitting and K-means assignment, so only retained foreground participates; the source mask still controls particle edges. Requires a real library. server.R:1453-1492
Non-spatial Clusters
strategy = "nonspatial_collapse"
Clusters retained foreground spectra by PCA + k-means into cluster-mean analysis units, then runs Ordinary Process, Identification, and Attach Best Matches. The protected background zero value and its source mappings never enter the PCA model or a cluster. Stops without Spatial Clusters' later spatial merge. server.R:1378-1451
Run library identification?
identification_active & lib_type != "model"
Combines the Identification on/off switch (default on) with lib_type != "model". Off: identify_blockwise() is never called; matches/pixel_matches stay NULL, so the Top Matches Table, match-based map colors, and Correlation Threshold (which needs identification) all become empty/unavailable. The AI Model Classification box further down has its own identical active-switch check and reaches several of the same outputs through a completely different path (ai_output()), NOT through matches/pixel_matches. server.R:1324-1325 · ui.R:205-208
Correlation Threshold on?
input$cor_threshold_decision
Requires identification to be on (UI note). Captured into run_settings$correlation_active alongside identification_active at the very start of canonical_state_gate, and feeds MinCor() (else -Inf, i.e. no-op). Gates the per-pixel correlation_keep mask used inside "Connected Threshold Regions" and "Spatial Clusters", and separately gates the Correlation Histogram and the correlation-based rejection shown on the Heatmap/Map Color Choices/Progress Bars. server.R:1015-1017, 1309-1310, 1495-1563
Library Identification
unique-value matching · indexed source projection
Spectrum Type defaults to All. The router combines the complete FTIR, Raman, and NIR full/medoid members on their union axis with intentional NA padding; explicit single-type choices select only that member. Dense objects retain blockwise matching. Compact maps match each unique stored value once, then project match rows through the source-to-value index when pixel-level thresholds, maps, or metadata require them. Collapsed units continue through canonical OpenSpecy. AI Model Classification reaches the same downstream result contract through its separate path. Plan 022 · global.R: app_select_library_spectrum_type() · server.R: identify_blockwise() · R/{match_spec,Specs_methods}.R
Attach Best Matches
attach compact dictionaries / dense metadata
Adds max_cor_name, max_cor_val, and material_class to dense metadata or compact source/value metadata dictionaries without expanding repeated labels. The resulting single object becomes canonical_state()$object. Plan 018 · server.R: attach_best_matches() · Specs metadata accessors
Build canonical_state
one Specs map or OpenSpecy unit object · Run-gated
The single expensive-analysis owner bundles one canonical object, matches, compact pixel/value mapping, partition, diagnostics, and the committed run-settings snapshot. Requested PCA, K-means, and Hilbert formatting runs here through full-object as_Specs(), after the base map has been completely read. These transforms consume foreground values plus mapping multiplicities without unraveling pixels: PCA background scores, K-means class, and Hilbert code are 0, disambiguated by the authoritative background mask. A single spectrum or collapsed unit result remains canonical OpenSpecy. Downstream consumers use representation-aware accessors rather than duplicate pipelines. Plan 018 · server.R: canonical_state_gate()
canonical_final() / DataR()
validated canonical Specs/OpenSpecy read
Validates committed state and returns its one canonical spectral object. Summaries, identification, quantification, metadata, maps, and downloads derive from this object through representation-aware accessors. The named Active Spectrum Inspection lane is the deliberate one-column OpenSpecy view boundary, including rejected clicked source pixels. Plan 018 · server.R: canonical_final(), DataR()
Quantification defined?
ratio_definitions() / measurement_definitions()
Purely data-driven, no switch: true if the user has added any peak-ratio or point-intensity definitions. Also Run-gated (quantified_data_gate), so it recomputes on the same Click Run event as canonical_state_gate, not independently. server.R:1676-1694
Quantification
app_attach_quantification()
Calls peak_ratio()/app_area_ratio() and point_intensity()/app_area_measurement() per user-defined row, adding numeric metadata columns only — never touches $spectra values. Its output (quantified_data()) is NOT a dead end: it feeds Download: Processed Spectra and Download: Top Matches directly (dotted rose lines), since both read quantified_data() rather than canonical_final() directly. Note: the package's quantify_particles() export is not used by the app. global.R:1374-1428
Pixel Projection
indexed projection · map only, Run-gated
Projects canonical unit/value results through the compact source index for heatmap coloring and rejection metadata. Coordinate and requested color columns materialize only for the plotted rows; spectral matrices do not expand. Dense objects retain the existing pixel-to-unit path. Plan 018 · server.R: pixel_projection_gate() · Specs accessors
Library type = model (AI)?
input$lib_type == "model"
Architecturally separate from Library Identification above — this path runs after canonicalization, not inside canonical_state_gate. It also disables filter/organism library controls and blocks strategies that need a real reference library. server.R:1324-1325, 1349-1354 · ui.R:228-241
AI Model Classification
ai_output_gate: match_spec(top_n = 5)
For an explicit type the router runs that FTIR, Raman, or NIR logistic model. The default All option runs every overlapping type-specific model with its wavenumber-mean filler, ranks class probabilities per spectrum, and retains the five strongest scores. Rank 1 alone feeds map colors, threshold summaries, and material identity; all ranks feed Top Matches and its download. The selected rank drives the optional coefficient overlay without rerunning classification. This path remains separate from identify_blockwise() and does not expose experimental random forests. Plan 025 · global.R: app_classify_model_library() · server.R: ai_output_gate()
Active Spectrum Inspection
active_spectrum_view() · indexed exact decompression
One aligned, one-column OpenSpecy object is the exact processed trace used by both Spectrum Plot and Quality Findings. A retained click selects its canonical unit. A rejected click takes that source pixel from the committed inspection source, applies the committed Run processing settings once, and labels it “rejected-pixel inspection”; it never substitutes zeros. Selection changes are narrow and do not recompute the whole map or library. Plan 018 target: a compact map resolves the clicked source and calls indexed decompress_spec() without expanding unrelated data. Retained foreground reconstructs through its stacked transforms as applicable. Mapping 0 bypasses PCA centering and every fitted model; a suppressed source returns an exact zero line labeled “background-suppressed,” with metric, bounds, sigma, and reason. Plan 018 · server.R: active_spectrum_view(), DataR_plot() · R/Specs.R: decompress_spec(index=)
Quality Findings
depends on: Active Spectrum Inspection only
For measured/retained spectra, assess_spec() and sig_noise() run directly on the displayed one-column Active Spectrum. A Plan 018 suppressed source instead reports its committed suppression evidence and bypasses misleading flat-spectrum or unavailable-S/N warnings on the intentional zero sentinel. No quality path reads heatmap or full-dataset values. Plan 018 · server.R: quality_report() · R/{assess_spec,sig_noise}.R
Download: Static Files
depends on: nothing analysis-related
User Metadata template / Test Data / Test Map are static bundled files, available the moment the app loads — not derived from canonical_state() or even a successful upload. The one deliberate non-canonical output in this diagram. server.R:2717, 2732-2737
Signal/Noise Histogram
depends on: Signal/Noise Compute + Recalculate Preview
output$snr_plot reads snr_preview(), populated only by Click Run or the Recalculate Preview button (both near the top of this diagram) from the live signal_to_noise() metric. server.R:2079
Particle Size Plot
depends on: Collapse particles = on
output$particle_plot reads canonical_final()$metadata$area, which only exists when particles were collapsed into units; empty for a non-collapsed map or single spectrum. server.R:2592
Sidebar Metadata Table
depends on: Batch Compact (off) or Collapse (on)
output$sidebar_metadata reads meta_cache(), from quantified_data() + canonical_signal_noise(); displayed signal-to-noise values use two significant figures while canonical values retain full precision. Its row structure changes drastically with Collapse: OFF → one row per uploaded spectrum/pixel, an identity that traces straight back to Read & Combine (long dotted line to the top of the diagram) rather than any processing step; ON → one row per collapsed particle/cluster, an identity decided at Collapse/Particle ID Strategy instead. Plan 018 target: compact maps materialize only the requested display columns/rows through indexed metadata accessors; the full spectral matrix is never expanded. Plan 018 · server.R: sidebar metadata cache · Specs metadata accessors
Download: Thresholded Particles (zip)
depends on: Collapse, Signal/Noise, Identification/AI
Details/processed/summary/particle-size figures always come from canonical_final() + snr_preview() — Signal/Noise thresholding alone is enough to produce this archive once Collapse has produced units. The correlation histogram and material-summary figures are added ONLY when identification produced values: correlation_values falls back through canonical_state()$pixel_matches or max_cor() (which is ai_output() in AI mode), and material_summary.png only appears if material_class exists in canonical_final()$metadata. The heatmap PNGs inside the zip come from map_color_choices()/heatmap_data_for(), so they also reflect whichever identification path ran. server.R:2781-2843
Partition Status Text
depends on: Particle ID Strategy
output$particle_partition_status reads canonical_state()$partition / $diagnostic / $pixel_to_unit, which record which strategy ran and how many units it produced. server.R:1589
Correlation Histogram
depends on: Correlation Threshold on, OR AI Classification
output$cor_plot uses best_match_rows(pixel_matches)$match_val only when correlation_active AND pixel_matches has rows; otherwise it falls back to max_cor() — and max_cor() is ai_output() in AI mode (server.R:1919-1933). Since pixel_matches is always NULL in AI mode, this histogram renders the AI prediction-value distribution whenever Library type = AI model, with no Correlation Threshold involved at all. server.R:1956-1970
Top Matches Table
depends on: Library Identification OR AI Classification
output$event reads top_matches() ← app_top_matches_table(). Real-library mode shows the selected spectrum's ranked references; logistic mode shows the selected spectrum's ranked class probabilities. Clicking a logistic row selects the exact class whose signed coefficients are rendered behind the Spectrum Plot. Rank and probability are display evidence only and do not mutate canonical analysis state. Plan 025 · server.R: top_matches(), selected_model_explanation() · global.R: app_top_matches_table()
Download: Top Matches
depends on: Identification OR AI, + Quantification
Two branches in the same handler: real-library mode reads identification_matches() + library_filtered()$metadata + quantified_data()$metadata (via quant_columns, from Quantification); AI mode instead does bind_cols(quantified_data()$metadata, matches_to_single()), and matches_to_single() in AI mode reads ai_output()$value directly. Either way quantified_data()'s columns are included — this is one of only two outputs that genuinely depends on Quantification. server.R:2742-2780
Material Class Plot
depends on: Attach Best Matches (or Collapse grouping)
output$material_plot reads metadata$material_class (collapse) or max_cor_identity() (non-collapse) — either way it needs Library Identification (or AI Model Classification, via max_cor_identity()) to have run. server.R:2600
Map Color Choices
depends on: Build canonical_state
map_color_choices() reads canonical_state()$object / $pixel_matches / $settings$collapse — available choices (Material, Correlation, Signal/Noise, ...) change with what that Run actually computed. server.R:2223
Spectrum Plot
depends on: Active Spectrum Inspection + optional match/model class
The processed trace is byte-for-byte the one-column object from Active Spectrum Inspection; the raw trace and optional selected reference remain labeled overlays. For one-spectrum logistic identification only, the selected Top Matches row adds a symmetric quantitative coefficient background: red negative, yellow near zero, green positive, with a weight color bar. It explains signed model influence, not causal peak importance, and is absent from library, no-identification, multi-spectrum/heatmap, and RF states. Plan 025 · server.R: output$MyPlotC, selected_model_explanation() · global.R: app_spectrum_plot() · R/interactive_plots.R
Selection Metadata Table
depends on: canonical_final() + click; Identification OR AI
output$eventmetadata reads match_metadata(), from selected_unit_index() + matches_to_single(). Real-library mode uses the selected reference row. Logistic mode joins only rank 1 for the selected spectrum into canonical metadata; lower ranked Top Matches remain interpretation alternatives and do not replace the winning identity. Row selection is set by clicking the Heatmap (dashed teal line below). Plan 018 target: a compact selection fetches exactly one aligned source metadata row and its value-level match fields. Plan 018 · server.R: match_metadata() · Specs metadata accessors
Download: Processed Spectra
depends on: Ordinary Process (values) + Quantification (columns)
write_spec() from quantified_data() + canonical_signal_noise(). The spectra VALUES in this download trace back only to Ordinary Process — Collapse/Strategy only decide which columns (units) exist. Quantification is not a dead end here: quantified_data() is the literal source object, so any peak-ratio/point-intensity columns the user defined ride along in the export; Identification adds metadata columns only, never touches $spectra. Plan 018 target: large compact maps use a compact RDS or a streaming expanded writer; no download may first materialize the entire dense object. Small/collapsed OpenSpecy outputs retain native behavior. Plan 018 · server.R: processed download · R/{io_spec,Specs}.R
Heatmap
depends on: Pixel Projection; Identification OR AI
output$heatmapA reads current_heatmap_data() ← pixel_projection(). Its available colorings change with upstream state: Collapse off shows per-pixel identification; Collapse on shows per-particle results projected back to pixels; Identification off shows only Signal/Noise-based coloring. Clicking selects a pixel/unit for Active Spectrum Inspection and Selection Metadata (dashed teal lines); the heatmap is never the quality-test data source. server.R:2523, 2475
Progress Bars
depends on: Pixel Projection + thresholds
output$progress_bars reads pixel_projection() plus canonical_state()$settings thresholds (Good Signal / Good Match / Good Identification). server.R:2282
