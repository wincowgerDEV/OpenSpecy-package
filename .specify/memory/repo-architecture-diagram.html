Repository Architecture

How this repository's top-level folders relate: which ones govern the rest, which ones make up the installable R package, how the bundled Shiny app becomes the hosted Shinylive site, and which folders test, benchmark, or document the others. Boxes are colored by tier — governance, R package core, verification/support, documentation, hosted deployment — solid arrows show "contains / builds into" relationships, dashed arrows show "governs / supports / documents" relationships. Every box is a real link: click or press Enter on a focused box to open that folder on GitHub (or, for the one dashed external box, the live hosted site) in a new tab. Hover or focus any box for a longer description first.

Companion to pipeline-diagram.html: that diagram is the canonical, Constitution-governed (Principle X) map of the bundled app's internal data-analysis pipeline. This diagram is a lighter-weight repository map at the folder level, not an app-internal one. It is not itself bound by Principle X, but it should still be kept roughly in sync when a top-level folder's purpose changes, moves, or a new one is added — see .specify/memory/constitution.md for the durable rules this repo follows.

.agents/
Codex skill definitions
Durable skill instructions for the Codex agent integration: speckit-plan, speckit-implement, speckit-constitution (hand-customized for this repo's single-plan.md workflow), plus the openspecy-* skills (public API design, Shiny app development, quality gates, hosted-app verification). Reaches Claude Code through git-ignored directory junctions under .claude/skills/. .agents/skills/
 .claude/
Claude Code skills, commands, settings
Claude Code's copies of the shared skills (kept in sync with .agents/ by the speckit-constitution workflow step), thin /speckit-plan, /speckit-implement, /speckit-constitution command wrappers, and local settings/worktrees. .claude/skills/, .claude/commands/
 .github/
CI workflows, issue templates
GitHub Actions workflows that gate and build the repo: R-CMD-check.yaml, deploy-shinylive.yml, deploy-cran-repo.yml, pkgdown.yaml, test-coverage.yaml, release-file-system-image.yml. These are what actually run the package checks and assemble the hosted site below. .github/workflows/
 .specify/
Spec Kit constitution, memory, templates
Durable project memory: constitution.md (the principles this repo follows, including the one behind this diagram), memory/pipeline-diagram.html (this diagram's sibling, covering the app's internal data-analysis pipeline instead of repo structure), feature plan templates, and helper scripts. .specify/memory/constitution.md
 R/
Package functions, exported + internal
The R package's actual functions: readers, process_spec(), match_spec(), library builders, and every other exported or internal function. Everything else in this tier tests, documents, or bundles around this folder. R/*.R
 man/
Generated Rd help pages
Roxygen-generated documentation, produced by devtools::document(). Never hand-edited directly (Constitution Principle VII) — update the roxygen comments in R/ and regenerate instead. man/*.Rd
 tests/
testthat suite (devtools::test())
The CRAN-facing automated test suite for current package behavior. Unlike workflows/ and benchmarks/ to the left, this folder is part of the package's required test/CRAN surface. tests/testthat/
 inst/
Bundled assets + the Shiny app
Installed alongside the package: example data and, most importantly, the bundled Shiny application under inst/shiny/ (below). Must stay small and network-free for CRAN readiness. inst/
 inst/shiny/
Bundled app (run_app())
The canonical local and hosted app surface: ui.R, server.R, global.R, and app assets. Launched locally via run_app(); also the source the hosted Shinylive build (bottom of this diagram) is generated from. Its own data-analysis pipeline is separately diagrammed in pipeline-diagram.html. inst/shiny/{ui,server,global}.R
 workflows/
Long-running reference-library scripts
Reproducible, version-controlled scripts (e.g. OpenSpecy_reference_library.R) that use R/ package functions on large external spectral datasets to build and validate the reference library. Not part of the CRAN test surface. workflows/
 benchmarks/
Old-vs-new performance comparisons
Keeps prior implementations of R/ functions for same-output performance comparisons (Constitution Principle VI). Required whenever a function change claims a speed improvement with unchanged output; excluded from CRAN submission. benchmarks/
 vignettes/
Package + app tutorials (Rmd)
Long-form documentation built with knitr/rmarkdown. sop.Rmd, advanced.Rmd, library-builder.Rmd, and spectragryph.Rmd document R/ package workflows; app.Rmd documents the bundled Shiny app in inst/shiny/. vignettes/*.Rmd
 docs/
Generated pkgdown reference site
pkgdown-generated function reference and article pages, built from the roxygen comments in R/ and the vignettes/ articles above. Regenerated by the pkgdown build process, not hand-edited (Constitution Principle VII). docs/ (pkgdown output)
 tools/wasm/
Builds the hosted Shinylive app
Scripts that turn inst/shiny/ into the WebAssembly Shinylive app and stage the public Pages shell: stage-pages-shell.R, check-pages-site.R, check-shinylive-export.R, and related helpers. Driven by .github/workflows/deploy-shinylive.yml. tools/wasm/
 site/
GitHub Pages landing shell
Hand-authored landing page and assets at the Pages root. stage-pages-shell.R copies this tree verbatim into the deployed site alongside the generated /app/ (Shinylive, from inst/shiny/ via tools/wasm/) and /pkgdown/ (from docs/) routes. site/index.html
 Live GitHub Pages site
wincowgerdev.github.io/OpenSpecy-package
The deployed result of site/ plus the generated /app/ and /pkgdown/ routes, published by .github/workflows/deploy-shinylive.yml. Not a repository folder — this box links to the live public site instead of a GitHub tree. https://wincowgerdev.github.io/OpenSpecy-package/
Sources: repository top-level folder listing plus tools/wasm/stage-pages-shell.R, .github/workflows/deploy-shinylive.yml, and .specify/memory/constitution.md. This diagram is a repository-structure map, distinct from and not bound by the Constitution Principle X rules that govern pipeline-diagram.html's app data-analysis pipeline coverage; update it when a top-level folder's purpose materially changes.
