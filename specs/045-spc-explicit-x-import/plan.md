# Feature Plan: SPC Explicit-X Import

**Feature dir**: `specs/045-spc-explicit-x-import`  
**Date**: 2026-10-07  
**Current tranche**: Correct single-spectrum SPC imports whose files store an explicit X axis, using the three supplied 1,024-point files as acceptance evidence.  
**Change class**: Package/scientific reader behavior.

## Goal And Scope

- Make `read_spc()` and `read_any()` preserve the stored wavenumber and intensity arrays instead of plotting the explicit X axis as a straight-line spectrum.
- **In**: valid new-format SPC files with floating-point Y data and the `TXVALS` explicit-X flag; regression coverage, documentation, NEWS, and direct checks of all three supplied files.
- **Out**: redesigning the public reader API, adding dependencies, expanding multi-spectrum SPC semantics, app UI changes, or rebuilding/deploying the hosted app.
- **Users**: package and bundled/hosted-app users uploading SPC spectra from instruments or conversion software.

## Requirements

- R1. For explicit-X floating-point SPC files, return the stored X coordinates as `wavenumber` and stored Y values as the sole `spectra` column.
- R2. Preserve established implicit-X SPC results, metadata overrides, `OpenSpecy` structure/alignment, and `read_any()` dispatch.
- R3. Reject truncated/invalid input through the established SPC backend rather than silently fabricating equal-length axes and intensities.
- R4. All three supplied files must yield 1,024 finite points, wavenumber range approximately -235.8155--4738.4359 cm^-1, distinct non-linear spectra, and maxima above 100,000 rather than the shared -180.918--4738.436 ramp.

## Technical Decisions

- **Approach**: remove the partial floating-point fast path and delegate all SPC layouts to the already imported `hyperSpec::read.spc()` parser, which owns `TXVALS`, `TXYXYS`, subheader placement, exponent scaling, and data-offset semantics. Preserve OpenSpecy's established first-spectrum conversion after parsing.
- **Public API**: no argument, default, return-type, export, or side-effect change. Primary workflow remains `"sample.spc" |> read_spc()` (or `read_any()`) returning one canonical `OpenSpecy`.
- **Dependencies**: unchanged; reuse required `hyperSpec` and `data.table`.
- **OpenSpecy contract**: `wavenumber`, one-column matrix `spectra`, and one-row metadata remain aligned; metadata and session attributes continue through `as_OpenSpecy()`.
- **Generated artifacts**: update `R/read_ext.R` roxygen and regenerate `man/read_ext.Rd` with configured roxygen2 8.0.0; do not edit generated files directly.
- **External resources/performance**: three local 8,736-byte user fixtures are read-only acceptance inputs; synthetic test fixture is generated in `tempdir()`. Runtime/memory are negligible; no benchmark is required because this is corrected behavior, not a same-output refactor.
- **Bundled Shiny app/pipeline diagram**: no source or pipeline change; uploads already call `read_any()`. Direct package-path regression coverage is the controlling evidence.
- **Hosted Shinylive/WebAssembly app**: `R/read_ext.R` is a shared hosted input, so run fast `-HostedAppStatic`. A genuine SPC upload smoke is required after an action-built wasm artifact contains this change; that exact-artifact check and deployment are maintainer-owned post-push work. No dependency/image/driver/pin change triggers a separate clean-rebuild rehearsal.

## Package Surfaces

- `R/read_ext.R`: respect SPC `TXVALS` when selecting the parser; clarify compatibility docs.
- `tests/testthat/test-read_ext.R`: generate explicit-X float SPC and assert stored X/Y, metadata, object validity, `read_any()`, and legacy fixture behavior.
- `NEWS.md`: record corrected explicit-X SPC decoding.
- `man/read_ext.Rd`: generated by `devtools::document()` only; `NAMESPACE` should remain unchanged.
- `benchmarks/`, `DESCRIPTION`, `inst/`, `site/`, vignettes/README/pkgdown, workflows: unchanged.
